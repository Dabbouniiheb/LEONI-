# Matrice de traçabilité du projet

## 1. Périmètre et méthode

Cette matrice décrit uniquement les fonctionnalités visibles dans le code source actuel de l'application `leoni-planing`. Elle relie chaque capacité aux acteurs, aux pages, aux routes HTTP, aux composants backend, aux tables, aux validations et aux preuves de vérification disponibles.

Dans les tableaux, tout chemin commençant par `routes/`, `controllers/`, `services/`, `models/`, `validations/`, `views/`, `config/` ou `server.js` est relatif au répertoire applicatif `leoni-planing/`.

Les niveaux de vérification employés sont les suivants :

- **Confirmé par le code** : le flux complet est identifiable dans les fichiers source.
- **Test automatisé présent** : un test `node:test` couvre explicitement la règle citée. La présence d'un test ne vaut pas preuve de son exécution dans un environnement donné.
- **Capture à réaliser** : la preuve visuelle doit être produite manuellement avec un jeu de données autorisé et anonymisé.
- **Non couvert par un test dédié** : aucun test automatisé spécifique n'a été trouvé pour le flux concerné.

## 5. Limites transversales à conserver dans le rapport

- Le frontend est constitué de pages HTML légères dont le contenu métier est injecté par JavaScript natif ; JavaScript est indispensable au rendu des pages protégées.
- La navigation visible est filtrée côté client, mais la sécurité déterminante reste appliquée côté serveur par les sessions, l'onboarding et les permissions.
- Les alertes du dashboard sont des messages calculés à la volée. Elles ne doivent pas être décrites comme un système de notifications persistantes ou comme un envoi e-mail/Teams.
- Le login actuel est exclusivement basé sur l'adresse e-mail.
- Le projet ne contient pas de reset de mot de passe administré par le Team Leader.
- `planning.horaire` est un placeholder affiché par l'interface, tandis que le temps réellement accumulé est porté par `work_hour` et les sessions de travail.
- Les écrans Users, Calendar, Leave Requests et Audit Logs ne proposent pas de pagination. Les logs sont limités côté serveur aux 100 événements les plus récents.
- Aucun test automatisé de navigateur, d'accessibilité, de responsive ou de parcours complet n'est présent dans le périmètre testé.
